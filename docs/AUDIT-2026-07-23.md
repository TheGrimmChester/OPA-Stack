[CRITICAL] (security) Hardcoded, default JWT signing secret allows token forgery
    file: auth.go:16  effort:S
    desc: The HMAC signing key for all JWTs is a hardcoded constant compiled into the binary and shipped with the source. Anyone with the source (public repo) or the binary can mint valid tokens for any username with role=admin, fully bypassing authentication and role checks in AuthMiddleware. VerifyToken uses this same static secret and never pins the allowed algorithm (no jwt.WithValidMethods).
    fix: Load the secret from a required env var/secret store at startup; fail closed if unset or equal to the placeholder. Rotate the secret, use >=32 bytes of random data, and pass jwt.WithValidMethods([]string{"HS256"}) to ParseWithClaims.

[CRITICAL] (security) Public /api/auth/register accepts arbitrary role -> instant admin privilege escalation
    file: auth.go:135  effort:S
    desc: Register is mounted with no authentication (main.go:1002) and copies the caller-supplied Role field straight into the users table, only defaulting to 'viewer' when the field is empty.     fix: Never accept role from the registration body. Force new self-service users to the lowest role, and require an authenticated admin (AuthMiddleware(..., "admin")) for any role assignment/elevation.
